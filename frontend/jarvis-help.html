JARVIS COMMAND CENTER

At your service, sir.

I run on your Windows PC or laptop, sir. Your command surface chooses its microphone and speaker, turns it on, and shows its conversations.

New installation? Start with the complete installation and tablet guide. The repository is public.

1. Install the optional voice components

Skip this if already installed. Open PowerShell in the project folder on the PC:

.\.venv\Scripts\python.exe -m pip install -r requirements-voice.txt
.\.venv\Scripts\python.exe scripts/install-voice.py
.\scripts\restart-server.ps1

The restart helper is for the installed background task. For a temporary terminal server, stop/start that server instead. Models are checksum-verified and stored privately; no other assistant's frontend is installed.

2. Save your OpenAI key on the PC

  1. Open the approved owner browser at https://localhost:18761, then choose More → Jarvis. Use your configured port if different. The Wi-Fi IP does not grant owner access.
  2. Get your API key from your OpenAI account. Expand Manage API key, paste it into the password field, and choose Save key. Do not put it in chat, source files, or Git.

The key is encrypted for your Windows account, never returned by the API or saved in browser storage. “Saved” confirms storage, not billing/model access. API billing is separate from a ChatGPT subscription.

3. Choose your microphone and speaker

  1. Keep Jarvis off while changing audio choices. Choose PC microphone; select your preferred built-in, headset or USB microphone. Tap refresh after connecting a device.
  2. Choose Jarvis speaker. Auto · built-in speakers prefers Realtek speakers independently of Windows' headphone output. Another listed speaker can be selected. A missing speaker produces an error rather than a headphone fallback.
  3. Choose Preview voice, then Turn on Jarvis. Speak toward the selected PC microphone.

Audio choices are also in More → System & controls. Allow desktop microphone access in Windows Settings if needed. The tablet browser does not record the command.

Try these

Say “Jarvis”, pause briefly, then say the command. “Hey Jarvis” still works. A short pause is more reliable than rushing the name and command together.

  • “Jarvis, open YouTube.” Opens the shortcut on the PC in Brave.
  • “Jarvis, open Steam.”
  • “Jarvis, open Discord.”
  • “Jarvis, turn the volume down.” Sends one Windows volume step.
  • “Jarvis, pause the music.” Toggles the current player once.
  • “Jarvis, how much memory am I using?”
  • “Jarvis, I want to play games.” Opens the game library without launching a game.
  • “Jarvis, what is the weather?” Opens your enabled Weather & air quality view.
  • “Jarvis, show the next F1 race.” Opens your enabled F1 countdown.
  • “Jarvis, show the clock.” Also ask for Home, Live performance, Apps, Hardware, graphs, Focus timer, Ambient, Now playing, settings, Device access, Rest & alarms, Widgets or Jarvis.
  • “Jarvis, enter rest mode.” Jarvis acknowledges, checks desk monitors, enters Rest and keeps listening.
  • “Jarvis, wake up.” Restores the desk monitors and your tablet's previous screen, preserving your alarm.
  • “Jarvis, search NASA for a recent mission update.”

Ask “Open Steam, show games and read my CPU” to combine a registered PC control, a screen request and a hardware read. Each turn permits one of each; physical controls run one at a time. Arbitrary commands, URLs, installation, shutdown, and smart-home controls are not supported. Native web search supplies current information; sources appear as links beside replies.

Screen changes reach already connected, visible approved dashboards. They do not launch apps/games, start timers, change settings or enter Rest. Enable Weather/F1 and select your weather city under System & controls → Tablet settings → Optional widgets first; missing setup opens that area. Voice choices hold automatic rotation for two minutes. Requests expire after ten seconds and do not replay on reload, return from hiding or reconnect. Finish an open dialog first; in active Rest say “Jarvis, wake up.” Reload both displays after updating and re-enable Jarvis after a backend restart.

Rest entry and wake use those fixed phrases while Jarvis is on and Windows is unlocked. Allow a few seconds for a USB-C dock check. Locking Windows or turning Jarvis off cancels pending actions. Set your alarm first in More → Rest & alarms; both commands keep it. Button entry also keeps an enabled Jarvis session running. Say “Jarvis, wake up” to leave Rest, or use Wake PC displays. The wake detector expects “Jarvis.” Windows lock pauses listening; voice wake does not unlock Windows.

If entry fails, Jarvis explains why; the exchange appears in History. Punctuation around “Jarvis,” optional “please,” and “enter rest mode, Jarvis” are accepted.

Continue naturally

After a reply, answer within 15 seconds without another “Jarvis.” With Jarvis off, choose Follow-up listening: Off, 15, or 30 seconds. Silence or a closing phrase such as “thanks,” “that's all,” or “goodbye” returns to wake listening.

This app uses gpt-transcribe for recognition and gpt-6-luna for interpretation/replies. Wake detection and Piper speech run locally on the CPU. After activation, a command clip of up to ten seconds goes to OpenAI, followed by text and context. Input closes during processing/speech. Audio is not saved.

Hardware alerts and the activity overlay

Alerts on / Alerts off controls warnings while Jarvis runs. CPU/RAM at 90% or above, or GPU temperature at 70°C or above, must appear in three fresh readings. Jarvis waits for idle wake listening, then speaks locally through its dedicated speaker without an OpenAI request.

All warnings share a one-hour cooldown across restarts. Alerts off cancels pending/current warning playback while leaving Jarvis on. Warnings are saved as system entries but excluded from conversational context. No warnings run while Jarvis is off or Windows is locked.

The Iron Man activity overlay on every screen follows wake/listening, understanding, processing, speaking, follow-up, and warning activity including Clock, Ambient and Rest. It shows live readings, leaves touch controls available, and respects reduced motion.

Saved history, stopping, and restarts

The latest 500 text exchanges, results and sources persist privately on the PC. Earlier conversations loads more. The latest six conversation exchanges provide OpenAI context across restarts. Only the approved localhost owner can Clear history, which also stops Jarvis.

Closing this webpage leaves Jarvis running. Turn off Jarvis releases the microphone and models. Windows lock pauses listening and prevents actions. A server restart starts Jarvis off: reload and turn it on again after a PC restart or backend update.

If something does not work

  • No sound: turn Jarvis off, check its selected speaker, refresh devices, and try Preview voice. Changing Windows' default alone does not change Jarvis's output.
  • No wake response: check its selected microphone and desktop microphone permissions. Reconnect/refresh the webcam, then enable Jarvis.
  • Commands fail: check internet access, API billing, key validity, and model access. Confirm the app is installed; YouTube requires Brave.
  • No key field: use the approved localhost owner browser rather than the tablet or Wi-Fi IP.
  • Missing models: complete step 1 and reload. Normal updates preserve the models/key; do not delete private state.

A room TV or speaker can trigger the wake phrase; wake detection is not speaker authentication.
