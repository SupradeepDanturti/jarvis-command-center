# Personal tools and memory

Implementation record · 2026-10-04 · extends [the assistant foundation](ASSISTANT_FOUNDATION.md).

## Enable Sheets

1. In your existing Google Cloud project, enable the **Google Sheets API**.
2. On the approved PC browser at **https://localhost:18761**, open **More → Personalization → Connections**. Enable assistant access and choose **Reconnect Google**, granting Calendar and Sheets access. Reuse the saved Desktop client; no new JSON is needed. Partial grants enable only the granted service.
3. For name discovery, enable the **Google Drive API** in the same project and reconnect for **Drive metadata** permission. No replacement client JSON is needed. In **More → Personalization → Sheets**, enable **Let Jarvis find and use my spreadsheets**. This account-specific setting starts off by default and allows discovery, reads and edit proposals without registering each file. Voice also needs personal context in Memory and listening enabled again after access changes.
4. Enter a spreadsheet name and choose **Find sheets**; leave it blank for recently modified spreadsheets. **More results** follows Google's next-page token. Search is restricted to non-trashed native Google spreadsheets in the account's user corpus, including accessible shared-drive items. It is a name search, not a cell-content search or an exhaustive shared-drive catalog. Google-reported incomplete searches are marked. Read-only files can be inspected but cannot receive edit proposals.
5. Choose **Explore tabs**, select a tab and **Read these cells**. Move through **Later/Earlier rows** and columns, or enter a starting row/column number. Tab lists page in groups of fifty. The dashboard reads up to 100 rows × 10 columns at a time; grid dimensions include blank allocated cells. Object and connected-data tabs are excluded from the editor.
6. Alternatively, expand **Or give access to one spreadsheet**. Register a friendly name and link/ID, choosing **Entire spreadsheet · all tabs** or **One specific range** (for example `Sheet1!A1:D20`). Up to twenty individual grants per Google account are stored. Existing registrations remain restricted to their saved range; they are never silently upgraded.
7. Edit individual cells, then **Preview change**. Check the file ID, exact target range, cell types and values before choosing **Apply these values**. Each read or proposal is limited to 100 rows, 20 columns and 1,000 cells, with existing per-cell/payload text limits. Whole-file access allows any such chunk, not one unbounded download or overwrite.

Google's `spreadsheets` scope grants spreadsheet-wide content access. Jarvis separately enforces the selected account-wide discovery setting or individual full-file/range grant. Drive's `drive.metadata.readonly` scope covers file metadata broadly, but this adapter requests only spreadsheet names, IDs and edit capability; it cannot download arbitrary Drive files or change permissions. Switching accounts hides other registrations and uses that account's separate discovery setting. Search results become opaque, account/generation-bound handles in server memory, expire after five minutes, and are cleared by stop/access changes; guessing a spreadsheet ID is insufficient. Search again after expiration. Spreadsheet creation, append, tab management and evaluated formula entry remain later milestones. [Sheets scopes](https://developers.google.com/workspace/sheets/api/scopes), [Drive scopes](https://developers.google.com/workspace/drive/api/guides/api-specific-auth), [file search](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/list), [tab metadata](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/get).

Updates start at the selected range's top-left cell and replace only supplied cells. RAW writes keep formula-looking strings literal. Multiline/tab-containing values are preserved in individual cell editors. Dashboard previews skip unedited cells, retaining their existing formulas and types. Numeric/boolean reads retain their types; select Text, Number or Yes/no when editing. Agent proposals use null to leave cells unchanged, following Google’s [ValueRange rules](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values). Previews last five minutes, stay in server memory, are consumed before dispatch and are discarded on stop, account/profile/memory/registration changes or restart. No automatic retry occurs. If a response fails after dispatch, the outcome is uncertain: check Google Sheets before preparing another change. Other editors may change the sheet after your read; this milestone does not claim compare-and-swap/ETag protection. [Read values](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/get), [update values](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/update).

Agent reads start with a bounded chunk, normally at most fifty rows and ten columns. Invalid rectangles are rejected before a provider call and before consuming the SDK read slot, so Jarvis can correct them in the same turn. A failed cell read does not mean account access is disabled: fixed validation messages explain the range bounds, and locally authored Google errors distinguish expired sign-in, denied access, stopped access and provider failures. Arbitrary exception text/provider payloads stay hidden. Multiple files with the same name require a choice; a partial chunk is labelled as such.

## View, edit and use local memory

Jarvis now writes durable user facts to topical Markdown files in **`.state/private/voice/memory/`**, shared by voice and typed chat and enabled by default. Tell it a lasting fact, or say **“Remember that I prefer morning meetings.”** Relevant file text reaches OpenAI when local memory is enabled. The agent reads a file before updating it, preserves unrelated facts and must provide evidence from the current request. Credentials, pasted documents, entire transcripts, temporary controls and account/web instructions are excluded by the trusted prompt and bounded parent tools.

On the approved PC at **More → Personalization → Memory → Local memory files**, inspect, edit, download, delete or disable the files. Owner changes stop current requests to clear stale context. File names, sizes, revisions and cancellation are validated; no arbitrary file paths are available. The folder is private plaintext under Windows ACLs and ignored by Git. See [artifacts and Markdown memory](ARTIFACTS_MEMORY_SPEC.md) for exact bounds, migration and verification.

Earlier facts move to reserved **`reviewed-facts.md`** before the old SQLite fact rows are retired. IDs and pending approval state remain intact. Expand **Earlier reviewed facts** to add/edit/approve/discard/forget these entries; their limit remains 200 facts of 500 characters. Pending inferred facts remain excluded from retrieval. Use this editor rather than modifying its metadata comments. The agent's topical-file tools cannot overwrite the reserved file.

**Use personal context with Jarvis** remains a separate, initially-off consent for Calendar/Sheets tools, briefing profile and earlier reviewed facts. Enable it after reading its disclosure; it does not control automatic topical-file memory. Assistant access, local memory and microphone listening have independent switches. Private account exchanges are excluded from model context with account consent/access off; local-memory exchanges are excluded with local memory off. Approved PC/tablet chat browsers may see the shared conversation, including personal replies, while Windows is unlocked, as explicitly authorized by the owner. Speech is audible near the PC; wake detection is not speaker authentication.

Ask **“What do you remember about my meetings?”**, **“Brief me for today”**, **“Find my Planner spreadsheet and read its first tab”**, or **“Change Planner’s Sheet1 cell B2 to 42.”** Account tools require the existing grants and personal consent. Sheet proposals still require owner review/apply on the PC. No unattended sheet writes or agent memory deletion are available.

**Preferences and working context** displays recent eligible conversation and the transient context prepared before a turn. **Download memory and context** exports the earlier reviewed facts, preferences and context views without credentials; topical files have their own downloads. This is not hidden model reasoning or a complete tool transcript. Full conversation history remains separately bounded to 500 exchanges; each turn uses the latest six eligible exchanges. Local file selection and earlier reviewed fact selection are separate bounded retrieval paths, supplied as untrusted data.

Forgetting a fact/file affects future retrieval and stops active requests. Earlier conversations and generated artifacts may still mention it; remove them separately. Deletion cannot retract already-sent requests, change Google data or erase exported copies. SQLite uses secure deletion for its retained tables; neither the database nor Markdown is DPAPI-encrypted.

## Harness and limits

All harness additions are in `backend/agent/`: `memory.py`, `sheets.py`, `personal_tools.py`, plus existing service, routes, fixed Google adapter and voice runner. Audio/process transport remains outside that folder. SDK imports stay inside isolated voice or typed-turn workers.

Typed model tools are `calendar_today`, `list_sheets`, `search_sheets`, `list_sheet_tabs`, `read_sheet`, `propose_sheet_update`, `remember_fact` and `search_memory`. `assistant_context` is a worker-only request, outside the model's registry. SDK registration/search discovery must precede tab discovery, reads or proposals, using an ID returned in the same turn. The runner permits six model steps with personal context, four otherwise, so search → tabs → read → proposal → reply fits. There is one registration/search, one tab-discovery, one cell-read and one proposal slot per turn; physical-control, screen and memory limits remain. Ask the user to resolve ambiguous names before preparing a write. The additional local tools are list_memories, read_memory and write_memory, plus create_artifact, list_artifacts and open_artifact. There are no generic HTTP, shell, arbitrary-file or subagent tools.

Network reads run outside the voice cancellation lock and recheck assistant/worker generations, desktop lock, deadlines and consent before delivery. Local provider requests disable retries, redirects and proxy inheritance. Writes require same-origin HTTPS owner approval of one concrete preview and recheck authorization before dispatch. Account changes, personal edits and stop discard stale context/previews; already-dispatched Google writes cannot be recalled.

Saved facts live in ignored `.state/private/voice/memory/` Markdown files. Preference/consent rows, conversation history, bounded artifacts and account-bound sheet registrations/discovery settings share ignored `.state/private/voice/history.sqlite3`. OAuth secrets stay in DPAPI ciphertext and access tokens stay in memory. Dashboard provider payloads and write previews are transient. No personal content enters localStorage, logs or Git. Consent explicitly governs sending account data to the voice model; dashboard reads alone never make a model call.

Gmail, Google Health onboarding, Calendar writes/selection, durable responsibilities and specialist delegation remain later milestones.

## Verification

Automated backend and fresh-browser QA use mocked Google/account/memory operations. They exercise memory bounds/persistence/retrieval, direct remember versus proposed facts, permission/account isolation, RAW values, preview expiry/consumption, uncertain outcomes/no retries, cancellation, redaction, owner-only management and approved shared chat conversation reads, safe rendering, and landscape/portrait/narrow layouts. Browser QA uses trusted certificates and revokes only its own credential.

The owner reports the earlier Google connection works. Live Sheets re-consent/read/write, physical microphone personalization and Windows lock transitions are not confirmed by automated checks. The existing connection and downloaded client have not been inspected through test tools.
