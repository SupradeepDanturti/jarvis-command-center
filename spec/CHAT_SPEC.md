# Unified Jarvis conversation

**More → Chat with Jarvis** works on approved PC and tablet browsers over HTTPS. It uses the voice agent's trusted prompt, model, Agent/Runner, fixed tools, citations, profile, memories and Calendar/Sheets consent. Typed replies never start microphone capture or speaker playback.

Voice and typed exchanges share the existing private `voice/history.sqlite3` table, its global 500-exchange bound, and the last six eligible completed exchanges (twelve messages) passed to each turn. There is no separate chat session, provider conversation ID, browser history database or extra transcript file. Switching input method or refreshing preserves completed context. Both inputs share local agent-written Markdown files in `.state/private/voice/memory/`, enabled by default. Relevant file text reaches the model when local memory is enabled; account tools, briefing profile and earlier reviewed facts retain **Use personal context with Jarvis** consent. Sheet writes remain proposals requiring the owner's existing review/apply workflow. See [artifacts and local memory](ARTIFACTS_MEMORY_SPEC.md).

One typed turn runs at a time in an isolated process. An OpenAI key, optional OpenAI/Agents dependencies, enabled Personal assistant and unlocked Windows desktop are required; audio models and microphone listening are independent. A spoken request cancels an in-progress typed request. Sending while voice is recording, transcribing or speaking returns busy. Stop cannot undo completed actions. The next completed turn reloads shared context.

The owner explicitly authorized the same assistant capabilities on the approved tablet. Chat exposes the **shared conversation, including personal voice exchanges**, to every approved PC/tablet browser while Windows is unlocked. Approve only trusted browsers. Existing account/key/profile/memory management and Sheets apply remain owner-only on direct-loopback HTTPS. Owner-only conversation deletion clears both typed and voice exchanges, stops current requests and microphone listening, and leaves saved facts separate.

Writes require the dashboard origin and valid browser cookie; HTTPS is required even on loopback. Messages are strict text of at most 1,000 characters. Control characters and extra fields receive redacted validation errors. The sender's credential, Windows lock, assistant generation, voice generation and 120-second deadline are checked before tools and before saving. Key/account/consent/history changes, Stop, shutdown, credential expiry and revocation cancel late work. Personal reads recheck cancellation. Optional dependencies stay out of the server process; provider tracing/storage remain disabled and exceptions are never logged with their contents.

Fixed tools retain SDK budgets and parent argument validation. Literal Rest commands use explicit phrase checks, the existing monitor adapter, fresh nonce/revision and cancellation; model tools cannot issue them. Navigation applies only to the requesting visible browser after completion, within ten seconds, with widget consent/dialog/Rest guards. Reloading or hiding never replays it.

The single conversation composition preserves the floating dock, with a scrollable thread, sources, earlier messages, artifact Open/Download links, textarea, Send and Stop. Enter sends; Shift+Enter adds a line. Text is escaped; source links require HTTP(S) without credentials. Conversation text never enters browser storage. Private rendered content and drafts clear on hiding, leaving Chat or losing approval. Returning rebuilds the surface without duplicating submit handlers.
