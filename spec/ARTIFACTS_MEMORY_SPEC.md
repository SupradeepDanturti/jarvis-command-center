# Jarvis artifacts and local Markdown memory

Implementation record · 2026-10-05 · shared by [voice and typed chat](CHAT_SPEC.md).

## Local memory

Jarvis automatically saves durable facts and preferences directly stated by the user into **`.state/private/voice/memory/`**. Examples include `profile.md`, `diet.md`, `fitness.md`, `home.md` and `preferences.md`. Both input methods read and update the same files. “Remember that I prefer morning meetings” also uses this path, preserving the exact stated fact. The folder is created at startup and persists across server restarts.

**More → Personalization → Memory → Local memory files** is the PC owner's inspector and editor. Local memory defaults **on**, as requested by the owner. Disabling it stops agent file reads/writes and excludes local-memory exchanges from subsequent model context; files remain available to the owner. Relevant file text is sent to OpenAI during enabled assistant turns. This is independent of **Use personal context with Jarvis**, which still governs account tools, briefing preferences and earlier reviewed facts. Account access and microphone listening retain their separate switches.

The trusted prompt instructs the agent to record stable user facts, preserve unrelated facts and replace contradictions. It forbids saving credentials, whole transcripts, pasted documents, temporary control requests or instructions from websites/account results. File contents are untrusted context data, never system instructions. The SDK must read the current file before writing it; the parent requires its SHA-256 revision and evidence occurring in the latest user request. Writes recheck enabled memory, assistant/worker generation, desktop lock, sender authorization and deadline, then atomically replace the file. A changed revision refuses the overwrite. Automatic extraction is model behavior; the exact explicit-remember path and cancellation/storage guards are deterministic.

Only lowercase topic names ending in `.md` are accepted. Paths, Windows reserved names, alternate extensions, symlinks and junctions are rejected. Agent tools cannot access arbitrary files. There are at most **20 topical files**, each **10,000 characters / 20 KB**. Each turn selects at most ten files and 10,000 total context characters by topic relevance, profile/preferences and recency. There is one topic-list, one memory-read and one write slot per turn. Owner-only edits and deletion require direct-loopback HTTPS, an approved owner cookie and same origin, and stop active requests to discard stale context.

Existing reviewed facts migrate to reserved **`reviewed-facts.md`**, preserving IDs, pending state and source metadata. The file is verified before retiring old SQLite fact rows; startup migration is repeatable. Its bound remains 200 facts, each 500 characters, in a file of at most 512 KB. Use the existing reviewed-facts editor for these entries; agent topical-file tools cannot alter this reserved file. Preference/consent settings and conversation history remain in SQLite; saved fact text uses Markdown. The private Windows ACL protects these plaintext files; they are ignored by Git and are not DPAPI-encrypted.

Forgetting a file or fact removes it from future retrieval. Earlier exchanges and already-created artifacts can still contain the same information: delete them separately if required. Deletion cannot retract requests already sent to OpenAI or erase exported copies. No claim of secure erasure of filesystem backups is made.

## Create, show and download artifacts

Ask Jarvis, by voice or chat, to **“Build an interactive HTML page for my workout plan”**, **“Create a PDF summary”**, or **“Open the report you created.”** `create_artifact`, `list_artifacts` and `open_artifact` are fixed tools shared by both inputs. Supported formats are HTML, JavaScript, CSS, Markdown, plain text, JSON, CSV and PDF. Separate JavaScript/CSS files are source previews and downloads; interactive HTML includes its own inline script/style. Existing artifacts must be listed before reopening; only returned opaque IDs can be opened.

**More → Artifacts** previews saved files on approved PC/tablet browsers. Chat replies also offer Open and Download links for returned artifacts. Voice opening uses the same short-lived screen-navigation delivery as other voice screens. Artifacts persist across restarts in the existing private voice database, bounded to the newest **20 files / 256 KB each**. Text is limited to 100,000 characters; PDF source to 20,000. The PC owner can delete a file with a second confirming click. Conversation deletion and artifact deletion are separate.

HTML executes only inside an iframe with `sandbox="allow-scripts"` and a matching response CSP. It has an opaque origin without dashboard cookie/DOM access. Network requests, external scripts/resources, frames, workers, forms, popups, downloads and top navigation are blocked. Generated scripts may implement interactions inside that page. Other source formats are HTML-escaped and rendered with iframe scripts disabled. Downloads require approved HTTPS and unlocked Windows. Downloaded HTML/JS is ordinary source outside the dashboard's preview sandbox.

PDFs are rendered from escaped text, headings, bullets and bounded pipe tables using optional ReportLab **inside the model child**. No supplied code, images, HTML, URLs, paths or external resources are evaluated. Output is limited to thirty pages and 256 KB. Locally served PDF.js renders pages into a canvas with page navigation on desktop/tablet; there is no CDN or browser plugin requirement. ReportLab is part of `requirements-voice.txt`, while the base dashboard keeps optional agent dependencies out of its process.

Creation/opening reuses current assistant/voice/sender authorization and cancellation checks. Store operations accept fixed format/content arguments and opaque IDs, never filenames, OS commands or argument arrays. Payloads, memory evidence and file content are omitted from action summaries and logs. Private rendered content clears on lock, hiding, leaving the page or losing approval. No artifact or memory content is saved in browser storage.

## Verification

Backend tests exercise the actual SDK/parent paths with mocked model responses, file revision/cancellation/capacity, durable Markdown migration, shared voice-to-chat recall, strict names/credentials, approvals/owner/origin boundaries, artifact pruning and safe PDF structure. Trusted fresh Edge fixtures verify interactive HTML isolation, local PDF pixels/download, memory editing/toggle/deletion, lock/reopen and four touch sizes. ReportLab output was rendered with Poppler and visually inspected, along with the PDF.js browser preview. Live cloud extraction/artifact generation, physical microphone handoff and physical tablet interaction remain owner acceptance checks; tests do not read the owner's facts, invoke Google or play/capture audio.
